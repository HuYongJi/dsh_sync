# 版本与兼容记录

## 0.11.0

- 本地／云端列表收起为两个点击入口；进入后搜索、多选，每批最多20个项目，无默认勾选。
- 本地项目各自新建云端项目；云端项目在一个明确的 Host 父目录下各自创建全新子目录和工作区，不关联已有本机目录。已有配对保持不变。
- 逐项持久化结果、目录所有权和未知登记状态；首次物化为专用下载 bootstrap，不自动上传竞争写入的本机文件，不启动会话／agent。
- 新增7个双向接入动作，原14个旧上传／备份恢复 RPC仍不存在。旧 pair API 保留兼容，但不在新版首次接入 UI中出现。
- 新增可协商的统一云端项目目录、代次游标和验证摘要索引；维持当前字节完整性检查。旧协议2服务器安全回退，生效范围和合成测量见[性能说明](<PERFORMANCE.md>)。
- 账号／准入改用轻量当前身份读取，不再反复扫描旧队列和全部工作区；保留认证、revision与更新保护。

本轮构建与完整测试结果单独记录于[测试说明](<TESTING.md>)，不复用0.10.0的724项或0.9.0的808项历史计数。未因此自动推送、安装或部署。

## 0.10.0

统一为双向同步一个项目操作入口；构建与测试结论见[测试说明](<TESTING.md>)，不代表已推送、安装或部署。

- 移除单向上传、旧自动上传设置、旧云端下载／恢复／导入／工作区登记界面，以及14个旧 Host RPC 动作。
- 原生命令移除 sync-push、sync-list、sync-restore、sync-import；仅保留双向 sync-status 和账号退出 sync-logout。
- 独立 CLI 移除 preview、push、retry、list、restore；在读取状态／凭据和网络请求之前拒绝。仅保留账号诊断与帮助。
- Host 不再运行旧上传 tick，旧 autoSync 配置不能复活它；原生凭据不回退到 CLI 登录。
- 云端选择器每个项目独立成行，不再标“旧版”；来源、版本数量、时间与同名项目标识用于区分，不作为路径授权。
- 保留云端数据、本机旧队列、内部迁移／历史校验和服务端兼容协议；不自动迁移授权，不全局阻止旧客户端访问。
- 账号续期、原生插件更新、双向配对、冲突、回收、归档导入、修复及共享预算继续保留。

0.9.0协议2服务端可继续使用，无需仅为本次产品入口变更重复部署。历史前端专属测试随被移除的功能退役；兼容存储／Host安全测试改用内部服务，新测试验证旧入口没有网络或写入效果。

## 0.9.0

历史0.9.0发布完成构建与808项全量回归；下列功能描述属于该版本，不是0.10.0已移除入口的操作指南。

- 显式配对后的同目录双向文件同步：逐路径共同基线、规范云端 head、不可变提交、回执与有限 CAS 重算。
- 冲突保留版本，跟踪删除与本机回收，独立确认恢复；不做自动文本合并。
- 有持久化意图的中断修复：保留最新本机编辑、备份和部分写入歧义，旧计划不会盲目重放。
- 可选设备续期，原生凭据隔离；登录变化不自动扩大项目权限。
- 会话／附件归档与显式安全子集导入分离，不启动 agent。
- 旧项目显式迁移、全部旧历史保留；已迁移项目拒绝旧写入与 v1 latest，仍允许明确历史 ID 的读取／新目录恢复。

- profile 共享10GiB软预算已接入，可明确保存1–1024GiB整数；未知计量失败关闭，不自动 GC 或改选项目。
- 健康缓存使用约15秒远端检查、最多30秒树元数据复用、每次 native 元数据检查与5分钟完整内容核验阈值；异常／变化不靠缓存跳过。
- 旧恢复结果跨重启持久化，但中断目录不续写／合并；消费标记和新会话 ID 留存。新增独立“添加到DSH项目”，仅登记工作区，继续同步仍要单独配对。

延续至当前版本的运行细节见[部署说明](<DEPLOYMENT.md#运行参数与本地预算>)。当前回归结果单独记录，不复用历史808项数字。

## 旧授权与服务器升级

- 旧上传选择不会被自动启用为双向配对。新配对确认会收紧对应旧上传路径，不把历史队列转发到另一个账号或目录。
- 从旧全局状态升级时，在当前 profile 重新登录并核对目录；不要复制 token／状态目录来“合并”设备身份。
- 0.9.0 使用 `/v2` 与版本2服务端存储，不能再沿用“仅升级客户端、服务器无需变化”的旧说明。先停止旧服务、备份整个数据目录，再升级服务代码。
- 新服务保留旧账号、blob 和检查点历史；服务内的单份升级前状态副本不是完整备份。不要手工修改 schema／serverId，或只替换一份状态文件来强行降级。

## 当前命令与账号 CLI

原生命令仅保留：

```text
/sync-status
/sync-logout
```

项目操作均在双向面板明确预览、确认。[CLI](<../src/cli.mjs>)只管理自己的账号诊断，默认状态目录为 `~/.dsh-sync`，可用 `--state DIRECTORY` 覆盖；不读取 GUI 原生凭据，不继承配对或续期权限：

```sh
node src/cli.mjs help
node src/cli.mjs login --server https://sync.example.com --username owner --password-file /outside-project/password.txt
node src/cli.mjs status
node src/cli.mjs logout
```

密码文件须在所有同步项目之外并受权限保护；不把密码放进命令行参数。旧项目操作命令被明确拒绝，不读取其状态、发送旧队列、下载或写入目录。

## 安装源排错

如果多个无关插件名被拼接到某个 GitHub 仓库 URL 后并报404，先核对 npm registry 是否误填了仓库网页，而不是复制更多 token 或关闭检查。

- 插件地址使用仓库地址、固定提交或本机安装包；npm registry 使用标准 npm 源或组织认可的源。
- DSH 安装可能解析当前 profile 的其他依赖；错误中的其他插件名不证明它们是本插件的依赖。
- 保留宿主版本检查与脚本批准，不自动卸载重装，不删除 profile、会话、凭据或同步状态。
- 原生更新只更新插件；安装后完整重启／刷新，云服务仍须管理员单独升级。
