# 0.10.0 部署、升级与运维

本文是管理员部署、升级与运维指南。示例路径须按目标环境核对；获取代码或安装客户端不会自动部署云服务、改动已安装 DSH 或启用项目同步。经授权部署的具体主机、备份位置与运维凭据保留在各环境的私有记录，不进入此公开仓库。

## 先升级服务，再使用双向同步

**原服务器、账号和完整数据目录可以继续使用。** 双向协议和设备续期要求0.9.0起的协议2服务端；早于该版本时须先升级。已运行0.9.0的服务器无需为0.10.0的入口简化再次部署，旧客户端的服务端兼容访问也不会因此全局关闭。

新版读取旧数据时会升级服务存储到版本2，并设置稳定的服务器标识。这里的**存储格式升级**不等于项目已经获得双向授权：未迁移项目仍走原有 v1 兼容边界，项目迁移仍需用户明确预览、确认。

旧二进制不理解版本2存储，应拒绝在该目录启动。不要修改版本字段或 serverId 绕过，也不要只替换一份状态文件来降级。升级过程留下的单份旧状态副本不是完整备份，不能代替所有 blob、历史、提交链和授权数据的备份。

### 已有服务的推荐顺序

1. 暂停各设备同步，记录正在运行的服务版本与数据目录；确认只有一个写进程。
2. 停止旧服务，确认已退出后，对**整个数据目录**做权限受限的完整备份，并检查备份可读。备份应存到同步项目之外，并另行加密保护。
3. 校验维护者提供的发布包及校验和，替换程序代码；不清空数据目录、不重新注册账号、不删除历史或 blob。
4. 使用原数据目录启动新版。检查本机健康接口、存储权限和错误日志；若状态／清单损坏，停止排查，不回退到“似乎还能读”的旧历史。
5. 核对 HTTPS 入口保留协议／功能响应头，再升级各设备插件，重启 DSH、刷新原页面。
6. 先使用合成项目验证登录、预览、双向变化、冲突／删除恢复与权限撤销，再由用户逐项明确配对真实项目。

回退也必须停服、选择相匹配的代码和完整备份，并意识到备份之后的提交可能无法保留。不要把旧授权族或旧 token 的状态恢复误当成当前安全状态；必要时重新登录并核对绑定。

## 新服务示例：Linux + systemd + Caddy

要求 Node.js24+、专用服务账户和 HTTPS 入口。服务器／CLI 使用 Node 内置模块，不需要安装一套 DSH 或第三方运行时数据库。**单进程、单写者**：禁止多 worker／多实例共享同一数据目录。

以下路径与域名仅为示例，请管理员先核对实际位置：

```sh
sudo useradd --system --home /var/lib/dsh-sync --shell /usr/sbin/nologin dsh-sync
sudo install -d -m 700 -o dsh-sync -g dsh-sync /var/lib/dsh-sync
sudo install -d -m 750 -o root -g dsh-sync /etc/dsh-sync
sudo install -m 640 -o root -g dsh-sync /opt/dsh-sync/deploy/server.env.example /etc/dsh-sync/server.env
sudo install -m 640 -o root -g dsh-sync /dev/null /etc/dsh-sync/password
sudoedit /etc/dsh-sync/password
```

先将发布内容放到示例程序目录。使用独立、随机的个人同步密码；初始化与改密要求至少8个 Unicode 码点、最多1024个 UTF-8字节，不复用模型服务密码。密码文件不应位于任何待同步项目。

根据[环境模板](<../deploy/server.env.example>)配置用户名、数据目录和密码文件；`SYNC_PASSWORD` 与 `SYNC_PASSWORD_FILE` 只能选一个。环境变量只负责初始化／旧状态核对，不是密码重置入口。成功改密后以持久化新密码哈希为准，旧 bootstrap 文件不会回写或恢复密码。没有通用的忘记密码找回接口。

核对 [systemd 模板](<../deploy/dsh-sync.service>)中的 Node 路径与程序位置后：

```sh
sudo install -m 644 /opt/dsh-sync/deploy/dsh-sync.service /etc/systemd/system/dsh-sync.service
sudo systemctl daemon-reload
sudo systemctl enable --now dsh-sync
curl --fail http://127.0.0.1:8787/health
```

服务[启动入口](<../server/main.mjs>)只允许 loopback 监听。不要把内部端口直接暴露公网；外层代理按[Caddy 示例](<../server/Caddyfile.example>)配置自己的域名：

```caddy
sync.example.com {
    reverse_proxy 127.0.0.1:8787
}
```

```sh
curl --fail -i https://sync.example.com/health
```

核对 `X-DSH-Sync-Protocol: 2` 与改密能力头；代理不应丢掉能力信息。健康响应不证明用户数据完整、备份可恢复或 TLS 配置已通过实机验收。使用真实证书，不关闭校验；仅 loopback 测试允许 HTTP，不跟随重定向转发授权。

### 登录期限

| 授权 | 行为 |
| --- | --- |
| 普通登录 | 访问凭据默认24小时；到期重新登录。 |
| 原生“保持登录” | 设备绑定的一次性轮换续期；默认30天空闲期限、90天绝对期限，访问期限仍受授权族到期限制。 |
| 续期拒绝、过期或回包未知 | 暂停并要求重新认证，不反复使用可能已消费的 refresh proof。 |

`SYNC_TOKEN_TTL_MS` 调整访问期限，不把续期授权变成永久授权。访问与续期秘密留在插件拥有的原生凭据记录，不进入浏览器或普通设置。更换密码撤销旧授权；登出远端撤销未知时，本机清除不等于远端已经撤销。

## 每台 DSH Host 的安装与授权

兼容版本以[包定义](<../package.json>)为准，本轮不升级 SDK peers：

- DSH session、session format catalog、LLM、Client UI Settings、Client Connection：`0.2.0-rc.2`。
- Cordis：`~4.0.4`；Node.js：24+。
- 原生插件管理器和 Host directory picker：`0.2.0-rc.2`，可选；缺失不应被“跳过安全检查”来修复。

用原生 Plugins 安装匹配发布版本，遵守兼容与脚本批准策略。仓库地址填写在插件地址位置，不是 npm registry。保留已构建的[Client 入口](<../client/dist/client.js>)；只改源码、只生成 tgz 或只刷新浏览器，不代表正在运行的 Host 已加载新代码。

然后按[快速开始](<../README.md>)完成登录、本机／云端选择、预览、确认启用。项目路径属于运行 DSH 的 Host；远程浏览器的本地目录与云服务器存储目录都不是该工作区。

- 每个设备／profile 独立保存身份与状态，不通过网盘复制 token、refresh secret 或状态目录。
- 新版不运行旧自动上传，旧队列保留且不会转换为双向授权。历史项目接入需要显式确认；多个 head 指定主版本，保留其他分支差异与全部原历史。
- 已迁移项目禁止 v1 写入／旧 latest；明确历史 ID 读取协议与内部新目录恢复校验仍保留，但不提供新版 GUI／CLI 恢复入口。
- 登录过期、退出、改密或身份变化后，先重新认证，再明确恢复配对；不能用新账号继续发送旧队列。
- 插件更新只调用原生 manager 更新插件，不更新云服务、不自动重启 DSH、不自动部署。

## 运行参数与本地预算

0.9.0已接入以下默认行为；它们是调度／资源边界，不是实时 SLA：

| 项目 | 默认行为 |
| --- | --- |
| 本机软预算 | **同一 profile 共享10GiB**，不是每个配对分别10GiB。高级设置可明确保存1–1024GiB整数，使用 revision CAS。 |
| 远端检查 | 健康配对约每15秒核对远端 head；网络退避、暂停和任务互斥会延后。 |
| 元数据提示 | 文件树元数据最多复用30秒；native 会话元数据每次检查。只有前后均确定、远端未变且本机无 dirty／待处理状态，才允许跳过完整内容扫描。 |
| 完整内容核验 | 健康、未暂停、可达且不在退避中时，距上次完整核验达到5分钟的调度检查强制执行；变化、未知提示、远端变化、dirty watch、部分事务或 native 活动不能依赖缓存跳过。 |
| 变化提示与调度 | watcher 提示约1秒去抖，Host 外层计时器约5秒，每轮最多处理3个绑定；不是毫秒级事件传递。失败采用指数退避，基础间隔封顶5分钟并附加抖动。 |

[计量实现](<../src/sync-budget.mjs>)只统计经验证的插件 stateDir（含共享 legacy spool、任务意图和会话缓存）及每个已知／暂停绑定的引擎和 applier 暂存／回收目录，重叠范围合并计数；不枚举用户项目正文，不计为整盘或云端配额。未知／不完整统计失败关闭，不能猜测可用容量。

Host 在全局操作锁下核对新的共享 blob、缓存和意图分配；每个引擎的额度先扣除其他绑定与共享占用。安全／结果元数据仍可持久化，因此预算是逻辑字节的**软快照**，不是文件系统硬配额。修改上限不改变项目选择、不自动清理，不借丢弃备份、墓碑或历史来绕过限制。

[元数据提示](<../src/sync-probe.mjs>)不能授权文件读写，也不能代替完整哈希验证。最近完成的远端核对与最近完整同步分别记录；只有提示确定且状态健康，缓存优化才生效。仍须监控实际磁盘余量。

当前插件版本为0.10.0，构建与回归结果见[测试与发布记录](<TESTING.md>)。该文另列历史0.9.0授权服务器的Linux/Node24验证；不能据此声称0.10.0已经部署或真实 DSH profile／GUI 已验收。

## 备份、锁与故障处理

- 本项目**不提供自动完整备份、自动墓碑／历史／回收 GC**。同步删除会传播，回收与不可变历史也不能代替独立备份。
- 云端备份应包含账号状态、访问／续期授权族哈希、blob、全部 v1/v2 历史、提交链与迁移信息；不要只备份内容文件。
- 正常关闭释放锁。真实进程强杀可能留下锁；必须确认没有使用该目录的活跃进程、核实准确目录和所有者、备份后再由管理员处理。不要批量删除锁或用重复点击夺锁。
- 注入异常／模拟重启测试证明日志恢复逻辑，**不是硬进程终止后自动清锁的证明**。未知回包先核对持久化结果，不能重做已可能落盘的导入。
- 原生导入可能部分持久化，不能通用回滚；先核对新会话 ID。活跃会话会推迟不安全操作，不自动停止 agent。
- 使用“核对中断事务”处理可识别的已接受部分应用，保留新编辑、备份和歧义；损坏根目录、备份或身份不是可随意重置的队列。
- 日志、路径、会话头部和备份可能含隐私；不要把完整诊断、配置或 token 贴到公开问题中。

## 换设备与已有数据

新设备先安装新版插件并登录，在 DSH 中创建或添加目标工作区（可为空目录），然后选择同一云端项目，预览并明确确认。目录与源设备不必同名，但必须是用户希望持续同步的内容。

0.10.0已移除独立的旧备份下载／新目录恢复／导入／登记工作区入口和对应命令；不再把它们作为换设备路径。现有云端历史、本机队列与恢复台账仍保留，内部兼容校验不等于公开操作入口。已配对项目的冲突、回收站、会话与中断修复仍分别预览和确认，不自动启动 agent。

本轮不部署服务端或修改真实 DSH profile；长期多机、当前 GUI、硬进程终止及压力验证须另行获得授权。核对清单与历史部署证据见[测试说明](<TESTING.md>)。
