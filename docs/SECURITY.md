# 安全设计与已知边界

此首版是个人、受信任设备之间的检查点同步，不是多租户 SaaS、公开备份服务或端到端加密保险箱。

## 数据边界

- 安装默认不上传。GUI 只授权用户在设置页明确勾选并保存的当前宿主项目；前端只提交 opaque workspace ID，Host 每次发送 blob/commit 前重新检查 registry、真实根目录、账号、设备与选择。独立 CLI 的 root 参数是另一条明确授权路径，不会自动继承 GUI 项目选择。
- 不扫描整个 home、DSH 配置、其他 provider 凭据或未授权工作区。会话通过宿主持久化 API 读取，只选择 cwd 对应的已落盘日志。
- DSH 管理的附件按其完整引用从附件 provider 读取，校验内容 hash。普通外部文件/外部 `present` 产物不会因历史里出现一个路径而被读入。
- 忽略常见密钥文件、缓存、版本库数据库和同步状态目录；目录使用**字面排除**，glob 特殊字符不能绕过。
- Host 使用可信 `profileContext.home/dir` 的原始及 canonical 路径保护 DSH 配置/账号目录，禁止同步这些目录本身或其内部项目；选择其祖先目录时排除相应子树。旧的不可变队列也要重新通过此检查，命中保护路径会整份阻止并保留本机，不会偷偷删改 manifest。
- 默认不上传 symlink、junction、硬链接、设备文件等。Windows `lstat` 可能不能识别 junction，因此还比较 realpath。
- manifest 包含源设备的绝对项目目录、设备 ID 和会话 ID，便于映射与溯源；0.6.0 的已鉴权项目目录也返回源路径与目录名称用于选择。路径本身可能包含本机用户名，只作为显示元数据，绝不直接当成本机恢复地址。
- 秘密文件名排除不是秘密检测。普通源代码、聊天正文、附件、产物和日志可能含 API key/私人信息；用户启用同步即需信任服务器管理员能读取这些内容。

## 凭据与网络

- 单用户由服务器管理员初始化，不提供注册接口。scrypt 密码哈希，随机 32 字节 token，服务仅保存 token 的 SHA-256、期限和设备绑定。
- 同步 token 不能执行宿主命令，只能访问此单用户同步存储。没有复制 DeepSeek、OpenAI/Codex 或其他 DSH 账号凭据。
- 0.2.0 插件原生授权只写自己的 `dsh-personal-sync/account-<profile-hash>` 记录。不同 profile 不共享 key，GUI 默认不回退全局 CLI token；native grant、非敏感本机身份和选择配置的 server/username/device 必须完整一致。
- GUI 密码仅保留在本次表单/登录或改密请求；提交、离开表单、身份变化或卸载后清空。不写浏览器 storage、普通配置、日志、会话，也不把 token 返回 Client。独立 CLI 的 token 存在自己的 state 配置中；POSIX 使用 0600 文件和 0700 目录。
- Windows 文件 mode 不能代替完整权限管理；state 目录必须由当前用户保护，不应放在共享目录。首版不提供额外的本机 token 加密层。
- HTTPS 必须由外层代理正确配置；测试才允许 loopback HTTP。不会跟随重定向转发授权头，无 `Access-Control-Allow-Origin: *`。
- 登出会撤销远端 token 并清理本地；已过期/已撤销的 401 也视为撤销完成。网络失败仍可清除本地，但明确报告远端撤销未确认，旧 token 可能有效至到期。
- 有待上传数据或同步历史时，更换服务器/账号须使用新 state 目录；发送任何 blob 前检查旧队列的 server、设备与当前授权根目录。

## 设置页的权限与生命周期

- 使用真实 DSH 原生 Settings slot、宿主 React 和 Connection RPC。Host 仅登记 `/api/dsh-personal-sync/{action}` 的 exact **POST streaming** 路由，不占用/覆盖 `/api` Gateway interceptor。
- Host/Origin fence 与 authority 绑定签名 cookie 由 DSH 在分派前检查。此权限代表当前宿主 operator，并非会话或项目 ACL；项目授权由本插件独立维护，不能用“已登录 DSH”替代项目勾选。
- 不把 Request 的 `dsh.internal` origin 当成浏览器地址，不开 CORS、不自己拼 localhost 绕过 Connection。
- 请求实际流量最大 64KiB，读 body 最长 10 秒；检查 JSON、字段白名单、RPC method/路径/rpcId、项目 ID 集合，错误使用安全常量，不回显密码或远端错误正文。登录还有本机速率限制。
- 非敏感 preferences 有严格版本/schema/revision；存在的 `null/false/0` 等内容视为损坏，不回退安装时自动同步权限。配置以原子替换落盘，跨窗口修改使用 CAS。
- 上传期间保存选择或退出先撤销排队工作、abort 活动上传并等待其结束，再确认新设置；已发送字节无法撤回。下载/导入任务期间其他设置写入会返回 busy；退出会取消并等待任务，已进入 native adapter 的导入只能等待其返回，不能回滚已落盘会话。插件卸载会等待活动任务/登录事务收尾。
- 登录仅接受远端白名单 token/expiry，不能让响应覆盖用户确认的 server/username/device。跨原生凭据/身份/设置写入失败或停止时尽力回滚并撤销新 grant；旧 grant 损坏不能阻止本地退出，也不能把已成功的新登录误报为失败。
- HTTPS server 地址由已授权 operator 明确输入，允许其自建网络服务器；不宣称实现 DNS pinning 或阻断所有私网目标。不得向不信任的地址提供密码。

## 0.3.0 修改密码

- 云端 `POST /v1/password` 只接受 username/currentPassword/newPassword；必须通过当前密码的 scrypt 校验，单有 Bearer token 不够。正确的当前密码不受旧 token 是否过期影响。
- 自 0.3.1 起，新密码至少 8 个 Unicode 码点、至多 1024 个 UTF-8 字节，不能与当前密码的 UTF-8 字节相同。登录请求上限 8KiB、改密 16KiB，均能容纳合法密码的 JSON 转义；改密与登录共享速率及 KDF 并发限制。
- KDF 使用认证快照，最后在独占写入中 CAS 核对 revision/hash/salt；并发改密只有一个旧密码请求成功，旧密码验证中的并发登录不能在改密后签发 token。
- 换盐/更新哈希/密码 revision+1/清空全部 token 在一次原子 state 提交中完成。所有旧设备 token 失效，现有 blob/检查点不删除，已鉴权的旧写入在最终提交前也会再次检查 token。
- Host 先用无密码的 `/health` 能力探测识别旧服务；设置页改密目标绑定已保存的 server/username/revision，不采用尚未提交的新地址。确认密码只在 Client 比较，不发送。
- 发出不可逆操作前，Host 先写 profile-scoped、无密码/token 的重新登录 intent。只有明确拒绝才能清除此轮 intent；成功、断线、5xx、损坏或超限成功回包都保留重登要求。不能把本地响应校验器的 status=400 误当成服务器 HTTP400。
- 成功后清理本机授权、关闭自动同步并要求新登录；远端已提交但本机清理/锁释放失败时仍报告已改密及本机异常，不假称远端回滚。新登录的授权和设置提交完成后，才清除 intent。
- 客户端在未知结果后只读取一次状态，不自动重发；旧 loggedIn:true 回包不能恢复已锁定的上传状态，必须显式重新登录。页面密码框在提交、取消、身份/revision 变化、离开表单和卸载时清空。
- bootstrap 文件只负责初始化。密码已轮换的 state 不读取旧 bootstrap 密码文件，不恢复旧密码，也不重写该文件。忘记当前密码仍没有找回/管理员重置接口。
- 设置页的常驻帮助/安全说明已移至文档；界面只显示简洁控件、状态和操作结果，不因此放松安全检查。

## 0.5.0 插件更新安全

- 更新是当前 profile 范围的安装代码操作，不是普通项目写文件，也不更新 DSH 主程序或云服务器。页面必须显式检查、核对版本与提交并确认安装；默认不联网检查、不安装、不重启。
- 只读元数据请求固定到本项目的 GitHub API 与该提交的 raw 内容，匿名发送、限制时间与响应大小、拒绝重定向，不附带同步 token、密码、项目/会话信息或 provider 凭据。不接受浏览器提供的更新 URL、命令、安装源或安装包路径。
- 默认分支的完整 40 位 SHA 绑定版本检查与原生安装，防止两次操作间分支移动导致换包；仅比较稳定语义版本，不降级、不强制覆盖同版本。固定仓库 + HTTPS + 提交固定并非独立签名验证，仍需信任维护者与 GitHub；SDK 不提供已安装来源/提交证明，不能声称验证了旧安装的来源。
- 已核实的 DSH 0.2.0-rc.2 `pluginManager` 通过 `ctx.get` 可选访问；缺失时仅禁用更新，不阻断同步。只更新健康的当前 profile 直接依赖，由原生 `installBundle` 完成锁、下载、兼容检查与安装，保留当前启用选择。不自行 spawn pnpm、不写安装目录、不自动卸载，也不添加兼容豁免或自动批准构建脚本。
- 确认意图绑定候选 ID/版本/提交/当前运行版本，Host 再次验证有效期与本机安装状态。异步安装使用插件自己记录的请求 ID，重复请求不再次调用原生安装；丢失回包只查状态，不根据 `changed`、事件通知或 `waitForInstall(null)` 推断成功。
- 上传、恢复与设置写入进行中不能开始更新。原生安装开始后保留重启屏障：成功、失败、取消或结果未知都不能保证安装树未改变，本插件停止后续写操作直到重启；不删除用户恢复目录、队列、会话或账号记录，不回滚其他任务。
- 取消只针对本插件自己发起的原生请求，`too-late` 不伪装取消。插件卸载时请求取消、等待本插件的只读检查/准入收尾，但不在自身 dispose 中等待原生安装，否则可能与宿主 HMR 独占队列形成互等；原生 manager 继续拥有安装、进程取消与最终收尾，相关 Promise 始终被观察。原生安装诊断、命令行输出和日志路径不整体发送到浏览器，仅返回安全状态码；脚本批准/兼容拒绝交回原生 Plugins 人工处理。
- 已有依赖替换后原生 manager 返回 `restart-required`，不会热替换 Host 模块；必须完整重启 DSH 再刷新页面。本次实现不自动重启、替用户推送发布或调用真实安装验证；测试使用合成 native manager 与元数据响应。

## 文件与检查点安全

- 路径只允许相对、可移植格式；拒绝 `..`、盘符/ADS、控制字符、Windows 保留名、尾点/空格、大小写碰撞、文件/目录前缀碰撞。
- 每个 blob 的 SHA-256 与大小都检查；会话/附件/产物在导入前再次检查恢复目录中的实际内容，不能只信任 manifest。
- Blob 内容寻址；检查点 ID 不允许替换，重复提交相同内容幂等。只有所有引用的 blob 已完整落盘，检查点才进入可见索引。
- parent 必须存在且属于同项目。过期 parent 或并行 root 会创建多个 heads，不按设备时间戳决定覆盖。
- 单文件 64MiB、总声明量 1GiB、20,000 文件、8MiB manifest；服务还有连接、请求体、超时、登录速率与 KDF 并发限制。
- 本地和服务都以独占锁防多写者。异常退出可能需要人工确认并移除陈旧锁；不冒险自动夺取可能仍活跃的目录。

## 0.6.0 目录选择与恢复计划

- 新图形界面不提交手填项目 ID/目标路径。云端源项目来自已认证目录；0.6.0 的名称/源路径取最后提交清单，并校验 SHA、大小和索引身份，不按设备时间决定分支。旧服务只查询已持久化的绑定；同名目录不是归属证明，缺失目录接口且无已知绑定必须升级服务器。
- 目标选择调用已核实的 Host `directoryPicker.capability()`，native 用 OS 选择结果，browse 用宿主单层目录列表；浏览器本机文件选择 API 不参与。可选服务缺失只禁用图形目标选择，不阻断其他功能。
- browse 只返回有界的目录名和不透明导航 ID，不读取文件内容、不遍历整个 home、不创建目录；检查上下级关系和当前目录身份，过滤隐藏、凭据、DSH/profile/state、已注册或历史绑定项目和链接。`sourceRoot` 不能作为本机目标，云端名称只可作为规范化单段子目录建议。
- 选择已有父目录后生成尚不存在的目标计划，显示最终路径并再次确认；冲突只改为另一个安全的新兄弟目录，绝不合并、覆盖或在选择阶段预创建。计划绑定登录/token、revision、项目/检查点、provider 身份和真实父目录 dev/ino/birth，过期/替换/链接变化均拒绝新任务。
- 写入中重复检查父目录和已保留根目录的真实身份，安全标记创建也不能跟随替换后的父目录。取消与首次独占创建竞争时，只有原位置未变才允许写完常量 `INCOMPLETE`；后续项目字节和完成清单仍受取消控制。计划过期不使已接受任务中途失效，重试原 requestId 不会绕过幂等规则。
- 新 GUI 的 `restore` 发送 `destinationId`；旧版本的显式绝对路径接口和命令保留兼容且仍受原有严格目录策略。UI 精简不削弱接口校验、更新重启门禁、档案安全导入或部分失败报告。

## 0.7.0 选择式批次安全

- 已选项目是下载包含列表，最多 20 项，独立于上传白名单；添加/移除/完成选择都不触发下载。0.7 固定模式按选定检查点恢复，0.8 新界面改为以下最新内容模式；保留旧接口不代表新界面继续要求分支/版本选择。
- 一次宿主父目录选择产生整个组的计划。组、全部项目/检查点、不透明目标、登录、provider 和父目录身份一起绑定，必须提交完整同组；混组、漏项、伪造句柄、重复项目/目录均拒绝。NFC 与大小写折叠的原子计划预留使同名/仅大小写不同的项目不会在尚未创建时就规划到相同目录。
- 整批所有目标先在独占锁内完成准入，才返回接受；准入前断线/过期不会写任何项目。接受后由 Host 拥有完整顺序任务，页面中止不取消其余项，也不会由浏览器逐个补发 restore。每次写入继续执行原有路径、哈希、身份和目录替换检查。
- 独立项目的校验/目录失败记录为单项失败并继续其他项；账号、权限、revision、退出或停止会终止剩余项，已完成项不会回滚/删除。批次受现有互斥与更新重启门禁约束；退出/停止取消并等待任务收尾。
- 请求 ID 与整个不可变选择绑定并保留结果，不驱逐后重新执行。批次只在当前插件生命周期与登录内有效，不声称崩溃/重启续传。文件成功但后续本机锁/状态收尾失败保留真实文件成功状态，同时返回 `DOWNLOAD_FINALIZATION_FAILED`，不吞掉错误或自动清理用户目录。
- 当前批次成功项的导入资格仅保存规范化清单摘要，不持有多份巨型清单，也不接受任意根目录。每项单独确认，导入前核验摘要与项目/检查点，准入时消费资格；部分持久化后新请求不能重做，详情保留可能已创建的会话 ID。新批次替换旧批次资格，普通旧单项目恢复仍保留其原有最新项约束。

## 0.8.0 最新内容的安全边界

- 最新模式授权的是“这些项目的最新内容 + 这些确切目标”，不是浏览器指定的历史 ID。请求、目录浏览句柄与计划必须带同一最新模式；检查点字段注入、模式交叉和 `latest:false` 均拒绝。旧固定模式仍保留原权限与兼容行为。
- 最新取服务端已成功提交索引的最后记录，忽略设备时钟，既不选未提交孤立清单，也不因多个 head 要求 GUI 选择。其他历史和并行 head 不删除、不合并；选择最新不表示把各分支改动自动汇总。
- 新批次在幂等结果查询之后、创建任何目标之前，重新读取各项目最新清单并检查 ID/项目/索引元数据。空、缺失、损坏或不匹配即拒绝该次整体准入，不回退旧历史。页面、生命周期和账号变动都能中止此阶段；之后再次复核目录、TTL 和身份。
- 接受后固定所解析的实际 ID，传输中不随新提交切换，也不改变已经确认的目标目录。相同请求重试仍返回首次结果，不重新下载较新内容；新请求才重新查最新。各项目按各自读取时刻确定，不承诺跨项目全局事务快照。
- 内部不可变检查点、SHA/大小校验、目录排他创建、摘要导入、部分失败和状态收尾警告全部保留。移除 UI 选择不等于移除校验或历史，也不授权覆盖已有目录、自动合并或启动代理。

## 恢复与执行安全

- 0.4.0 的图形化浏览/恢复只走已鉴权的原生 Connection。`projects/checkpoints/restore/import` 均绑定已保存的 server/username/revision；云端目录为认证后的只读项目摘要，不包含凭据。下载不要求预先选择上传项目，也不会代替用户授权上传。
- 图形化恢复需要明确确认项目与宿主新目录；旧固定接口指定检查点，新界面由 Host 解析并固定最新已提交内容。核验实际清单属于所选云端项目后才写文件。禁止目标位于 DSH home/profile/state 或已注册工作区内，拒绝目录跳转、非法目标与已有目录；不依据云端 sourceRoot 自动选择本机写入位置。
- 下载和导入是 Host 端异步任务，页面只轮询状态。关闭页面不代表取消，超时不自动重发；重复 requestId 在当前插件生命周期内不重做，容量用尽明确拒绝。任务记录不跨插件重启持久化，重启/断线后先核对恢复目录及会话，不能假设未完成的回包代表没有写入。
- 图形化导入仅接受当前插件记录的已成功恢复结果，并须再次确认；只下载不会创建会话或启用自动上传。导入结果保留成功/跳过/失败数量及新会话 ID，跳过或部分失败不标成全成功；未挂到 workspace 的已落盘会话也需人工核对。
- 恢复目标必须不存在，通过独占创建保留目录，再逐文件 `wx` 写入；绝不合并/覆盖现有目录。
- 失败留下 `INCOMPLETE`，不伪装成功。仅删除本次自己创建并重新验证的完成标记，不清理用户文件。
- 会话档案采用版本化逻辑封套，不覆盖宿主物理日志。导入调用 native format validator，并重放 native assistant stream verifier。
- 导入只持久化一个全新独立会话：不创建/恢复 agent，不继承待处理 inbox、运行任务、父子层级或未经适配的权限/goal/schedule 状态。
- 仅理解的普通完整会话可续接。未适配的领域即使已归档，也会拒绝导入并返回原因。未知格式 fail closed，不盲目删掉字段后宣称兼容。
- 路径映射只改确定的结构字段；不会批量替换历史自然语言或命令文本。恢复文件也不会被自动运行。

## 无法保证的事项

1. **不是 E2EE。** TLS 保护传输；服务器磁盘和备份需要另行加密，服务器管理员可看明文。
2. **不是全项目原子快照。** 会检查逐文件稳定性，并在排队前重新检查宿主会话 revision、高水位和活动；外部编辑器仍可能在不同文件间产生逻辑上不同步的瞬间。重要迁移前先停止编辑/构建。
3. **不是恶意同用户进程隔离。** Node 路径校验和 `O_NOFOLLOW`/独占写能挡静态穿越，但不能提供所有平台上的无竞态目录句柄安全。不要让不受信任进程在快照/恢复时改写这些目录。
4. 不保留 ACL、扩展属性、稀疏布局、符号/硬链接、空目录或所有 POSIX 权限；只保留普通文件内容与可执行标记。
5. 没有自动云端/本地 GC、磁盘总配额、MFA、密码恢复、自动密码轮换、设备撤销列表、删除同步、冲突自动合并、实时协作或无限版本兼容。
6. Native 导入没有通用事务回滚；provider 部分失败会返回可能已创建的会话 ID，须人工核对。
7. 自动同步依赖 DSH 进程运行；首版使用轮询，离线时保留最后排队的检查点，不宣称捕获每次编辑。
