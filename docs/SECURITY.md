# 安全模型、数据边界与已知限制

本文描述0.9.0的安全约束，不是部署或真实 GUI 验收证明。本项目面向个人、受信任设备与自管服务器，不是多租户 SaaS、秘密保险箱或端到端加密备份系统。

## 授权不是“已经登录”

- 安装、登录、浏览项目均不默认选择工作区或上传。双向写入需要本机工作区与云端项目的明确配对、预览和确认；旧上传选择不自动升级。
- 本机路径来自 **DSH Host** 的工作区 registry 或受限目录选择，不是浏览器电脑上的路径，也不是云端 `sourceRoot`。同名目录不证明同一项目。
- 配对绑定服务器源地址、稳定 serverId、账号、设备、授权 epoch 与真实根目录身份。目录替换、账号变化、重新授权和策略变动都要重新核对，不能静默改绑旧队列。
- 授权回调、真实根目录、当前忽略／保护策略在发送或应用前复核。取消／暂停阻止后续动作，但不能收回已发送字节或撤销已经落盘的结果。
- 入站应用检查 native 活动状态；缺失或无法确认所需能力时保守延后。不自动停止、重启、创建或恢复 agent。
- 服务器 bearer 表示该个人账号的存储访问，不是本机文件权限。DSH Host/Origin/operator 权限与本插件的项目授权是不同边界。

## 凭据与设备授权

服务器使用 scrypt 密码记录，访问与续期秘密均由随机值生成，服务保存其哈希、期限、设备绑定及授权族状态，不保存明文密码。

- 普通访问期限默认24小时；可选“保持登录”通过原生凭据记录保存轮换式设备续期授权，默认30天空闲期限、90天绝对期限。
- 续期是一轮一用的 proof 轮换，不是幂等提交。过期、拒绝或回包／本机持久化结果未知时要求重新认证，不能盲目再用可能已消费的 refresh proof。
- 自动续期不改变项目授权 epoch；显式登录、退出等身份动作改变授权边界。重新登录不等于自动恢复旧配对；需要核对并显式恢复。
- 原生账号记录、非敏感身份设置与配对身份必须一致。GUI 不回退不相关 CLI token，不跨 profile 分享凭据。
- 密码只用于当次登录／改密。访问、refresh secret 不返回浏览器，不进普通配置、引擎日志、会话或包产物；不复制 DeepSeek、OpenAI/Codex 等其他 provider 的凭据。
- 原生凭据存储仍依赖宿主与操作系统权限；不宣称额外实现了一个本机加密保险箱。Windows mode 位不能替代 ACL，不把状态放在不受信任的共享目录。
- 退出可清除本机授权，但网络失败时不能声称远端授权族已经撤销；旧授权可能在服务器期限内仍有效。

改密必须验证当前密码，单有 bearer 不够。密码哈希轮换与旧访问／续期授权撤销一起提交；未知回包保持重登要求，不重发改密。bootstrap 环境或密码文件不是重置已有密码的入口。现阶段没有 MFA、完整设备管理或忘记密码找回流程。

实现参考：[设备授权](<../server/device-auth.mjs>)、[Host 凭据生命周期](<../plugin/controller.mjs>)。

## 网络与部署信任

- 非 loopback 地址要求 HTTPS；不会关闭证书验证或跟随重定向转发授权。TLS 通常由外层代理提供，本服务只监听 loopback。
- Host operator 可以明确选择自己的服务器；不声称提供 DNS pinning 或阻断所有私网目标。不要把密码交给不信任的地址。
- **不是 E2EE。** 服务器管理员能读取文件／会话／附件；内容哈希证明完整性，不提供保密性。服务器磁盘、运维日志和备份应另行保护。
- 单进程独占存储，没有多实例共享目录的协调协议。请求体、时间、密码计算并发、速率及数据大小均有限制。

管理员升级／备份步骤见[部署说明](<DEPLOYMENT.md>)。

## 路径、忽略策略与元数据隐私

默认禁止同步常见凭据、密钥、版本库数据库、依赖缓存、DSH/profile/同步状态以及链接／特殊文件。Host 保护可信 home/profile/state 的真实与原始路径；其祖先作为项目时，相关子树仍必须排除。状态目录名中的 glob 字符按**字面路径**处理。

项目根目录的 `.dsh-syncignore` 是**本机策略文件**：仅相对排除 glob，不支持反向包含。v2 不在入站文件中同步它，另一台设备不能借替换忽略文件扩大这台 Host 的权限。策略变化会使旧验证缓存失效；不可变旧队列必须重验，不能通过改写清单、跳过检查或“再次重试”绕过。

路径必须相对、可移植且符合规范；拒绝穿越、盘符／ADS、控制字符、保留名称、尾点／空格、大小写和文件／目录冲突。校验祖先及 realpath，不只依赖 Windows `lstat` 的链接标志。普通文件读写也校验单链接、大小与 SHA-256。

路径和头部同样是数据：

- v1 清单可能含源设备绝对目录与会话 ID。
- v2 文件清单主要使用相对路径、显示名称、设备／项目标识；这些仍可能透露项目名称或组织信息。
- 会话归档的来源、native header、正文、命令和附件可能包含绝对路径、本机用户名与其他敏感内容。

**文件名过滤不是秘密扫描器。** 普通源代码、日志或用户粘贴的聊天文本可能包含 API key。不要把整个用户目录、服务数据目录或备份目录当作普通项目。忽略某个项目文件，不等于对既有会话正文做内容脱敏，也不能撤回此前已上传的数据。

参考：[快照与共享排除策略](<../src/snapshot.mjs>)、[v2 清单约束](<../src/sync-protocol.mjs>)。

## 同步与冲突的安全语义

v2 以规范云端 head 的 ID、revision 和不可变清单做 CAS；设备时间不能决定覆盖。请求与内容绑定，重复原请求核对原回执，不能用同一请求 ID 换内容。

本机采用**逐路径共同基线**，不是把一次远端 revision 当成所有文件都已落盘的证明。提案从远端当前状态出发，保留本机未管理／忽略的路径；只对已跟踪且有依据的删除发出墓碑。

- 干净变化可以双向传播；同路径并发变化保留冲突版本，不自动文本合并或覆盖活跃本机编辑。
- 入站先准备并验证数据，按预期旧状态保护原内容后才独占发布；发现新编辑即停止对应不安全应用。
- 只有已确认、已实际物化的路径推进共同基线；已确认云端提交、本机部分应用与本机收尾失败分别记录。
- 旧回执未确认时先查回执再决定是否重放原请求；策略变动使不再合法的旧提案退役，不偷偷修剪旧描述符后继续上传。
- 文件、删除／替换副本、冲突版本和归档各有边界。同步删除不等于不可恢复抹除，但也不代表拥有独立离线备份。

参考：[三方规划](<../src/reconcile.mjs>)、[本机应用日志](<../src/sync-local.mjs>)、[持久化引擎](<../src/sync-engine.mjs>)、[云端提交链](<../server/sync-store.mjs>)。

## 显式修复不是清空队列

“核对中断事务”先生成有期限的持久化计划，再明确确认。它不直接重放已阻止的写入、不重置共同基线、不删旧备份。

- 预览不写项目文件；确认前再核对身份、根目录、策略、旧描述符／日志和当前观察值。
- 只有预览时缺失且仍缺失的主文件，才可能从**经过验证、确属旧事务**的备份独占补回。新出现或不同的已有文件保留，不覆盖。
- 本机自定义忽略路径的安全补回属于本机恢复，不授予网络上传权；强制保护路径不能借修复写入。
- 部分发布／修复的未知结果带歧义标记，即使远端内容恰好等于旧基线，也不会把截断文件当作干净编辑发布；可核对相同内容或通过明确冲突解决继续。
- 停用旧待处理事务、推进已验证基线并记录歧义／修复结果，在一次引擎状态替换中提交，不提前清掉证据。
- 新策略阻止已接受修复时，可以**显式新预览**替代；旧请求保留终态和历史，不因策略再改回来复活。
- 只读结果查询区分未接受、待完成、完成和被替代；不把准入前拒绝误报为已写入，也不把未知当作全成。

这不是目录级原子事务，也不会回滚其他程序的编辑。根目录／身份／备份损坏、没有可证明的提交结果时保守拒绝。实际进程强杀留下的锁不会被自动抢占；故障注入测试不能代替真实硬终止验收。

## 会话档案与安全导入

原生会话只从当前明确项目的持久化接口读取。附件按其完整引用读取并校验；不会因为日志出现某个外部文件路径，就扫描或上传该外部目录。

档案引用追加、按内容去重；捕获的新引用必须由当次受控 spool 写入证明所有权，缓存里碰巧存在某个旧 blob 不是重新上传它的授权。当前根目录／策略／账号检查同样约束归档发送。

**归档范围比安全续接范围大。** 未适配的 goal、schedule、权限、subagent/team/workflow、图像 offload 或插件领域，可验证的日志不等于可以恢复运行的状态。导入必须：

1. 由用户单独选择档案、预览、确认；自动同步不自动导入。
2. 验证 native 格式、事件流、附件／产物闭包及当前目标文件状态；不靠删除未知字段假装兼容。
3. 使用新会话 ID，不恢复 agent、运行任务、待处理 inbox 或未经适配的层级／权限。
4. 只映射确认过的结构化路径，不批量替换历史自然语言／命令文本。
5. 保留部分持久化结果与可能已创建的 ID；未知导入结果不自动再次执行。

原生 provider 可能没有通用回滚接口。“已归档”“预览成功”和“所有会话都能续接”不是同一件事。参考[会话归档与导入](<../plugin/session-sync.mjs>)、[native 适配](<../plugin/dsh-adapter.mjs>)。

## 旧历史、部署与客户端边界

- 存储升级到版本2不删除旧历史，也不自动把旧上传许可变成双向许可。
- 旧项目迁移需核对完整 head 集合与明确主版本；保留全部旧记录／分支差异，不从缺失路径推断历史删除。
- 迁移后的 v1 写入与旧 latest 被围栏拒绝；明确历史 ID 读取和新目录恢复仍允许。
- 新目录恢复只创建尚不存在的目标，不合并／覆盖。失败目录保持不完整状态，不能据此直接导入。
- 旧恢复台账跨重启保存，按身份命名空间、授权 epoch 和摘要核验；中断目标记为失败／取消，绝不自动续写或合并。已完成最新恢复／当前批次项的导入资格、消费标记与预分配 native ID 持久化；未知结果不重复导入。
- “添加到DSH项目”是另一次明确确认，只创建／复用工作区，不创建会话、启动 agent 或加入同步选择。继续双向同步仍需独立配对授权。
- 浏览器只通过原生 Connection RPC；Host exact POST 路由复用 Host/Origin 与会话验证，另做项目授权、字段白名单、revision／意图检查。UI 隐藏按钮不是安全边界。
- 插件更新固定来源和完整提交，由原生 manager 处理安装、版本与脚本批准；不自行运行安装命令、降级检查、复制其他 profile 或更新云服务器。开始替换后即使失败／取消也可能需重启。

## 不提供的保证

- 没有全项目目录事务、所有平台的无竞态目录句柄隔离，或恶意同用户进程隔离。不要让不受信任进程改写项目及插件元数据。
- 不完整保留 ACL、扩展属性、稀疏布局、链接、空目录及所有 POSIX 权限；普通文件内容和可执行标记也受平台语义限制。
- 不保证捕获每次编辑、实时协作或离线无限积累；Host 停止就不会持续工作。元数据缓存只优化健康、确定、未变化的状态，不授权数据读写；dirty、部分事务、native 活动或未知探测不能用缓存跳过，完整内容仍按5分钟阈值强制核验。
- 没有自动完整备份、自动云端／本机历史、墓碑或回收 GC。默认10GiB软预算由同一 profile 共享，只计插件状态与已知／暂停绑定维护区；不计用户项目正文或云端磁盘。未知统计失败关闭，不猜容量；安全／结果元数据仍可持久化，因此不是硬磁盘配额，见[运行参数](<DEPLOYMENT.md#运行参数与本地预算>)。
- v2单 blob 上限64MiB、清单上限8MiB、最多20,000项（文件、墓碑、档案和冲突相关项／变体计入）、唯一引用 blob 总量上限1GiB；v1仍按旧检查点规则校验。达到限制会停止，而非静默删除历史。
- 尚未完成真实安装 profile、完整0.9.0 GUI、Linux/TLS、跨真实设备或强杀／断电验收；具体分层与证据见[测试说明](<TESTING.md>)。
