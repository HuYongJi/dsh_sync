# DSH 个人云同步 · 0.10.0

**本地运行、显式配对、持续双向同步。** 云端负责认证与保存数据，不运行你的项目，也不替代 DeepSeek、OpenAI/Codex 等模型账号登录。

> **0.10.0只保留双向同步这一条项目操作流程。** 单向上传、旧备份下载／恢复入口和相关命令已移除，旧自动上传不再运行；已有云端历史与本机队列不会因此删除。构建与入口检查通过，完整回归724项通过、零失败；详细证据与交付边界见[测试说明](<docs/TESTING.md>)。真实 DSH profile／GUI 仍需单独验收。

## 快速开始

同步服务器需支持协议2（0.9.0起）；已经运行0.9.0服务端时，本次入口简化不要求再次升级服务器。在各设备安装新版插件。兼容目标为 **DSH 0.2.0-rc.2、Session format 4、Cordis 4.0.4、Node.js 24+**。

1. 打开 **设置 → 个人云同步**，输入同步服务器的 HTTPS 地址、账号和密码，点击 **登录**。可选“**在此设备保持登录（最长90天）**”；密码不会因此被保存。
2. 在 **双向同步** 卡片点击 **连接项目／配对项目**。选择一个**本机工作区**，再选择已有云端项目，或明确选择“创建新的云端项目”。没有工作区时先在 DSH 中打开或添加它。
3. 点击 **预览变更**，核对上传、下载、删除、冲突和阻止项。目录同名不是配对依据；不要把不相关项目配到一起。
4. 点击 **确认并启用**，才授权该配对持续双向同步。在第二台设备重复上述步骤，选择同一个云端项目。

**安装、登录和查看项目不会默认选择工作区或上传。旧版的上传授权也不会自动变成双向写入授权。** 每个目录均属于运行 DSH 的 **Host 机器**，不是远程浏览器所在的电脑。

## 同步时会发生什么

| 情况 | 行为 |
| --- | --- |
| 一端新增或修改，另一端未改动 | 自动传递文件变化；不是自动文本合并。 |
| 两端修改同一路径，或修改与删除冲突 | 保留内容版本，冻结冲突路径；通过“冲突”预览后明确选择保留双方、本机或云端版本。不会按设备时间决定谁覆盖谁。 |
| 已跟踪文件被删除 | 传播有记录的删除；替换、删除前保留本机恢复副本，可从“回收站”预览恢复。已有目标不被覆盖。 |
| 首次配对、忽略路径或未跟踪路径缺失 | 不把“本机没有这个文件”直接当作删除指令。 |
| 离线或响应丢失 | 保留本机捕获与待处理意图；核对已提交回执，不盲目创建另一份写入。 |
| DSH 会话正在活动 | 推迟不安全的入站文件应用，不替你停止、重启或创建 agent。 |

自动同步由 Host 调度，不依赖设置页保持打开。可在项目行暂停或“立即同步”；暂停不会删除本机文件、云端历史或回收副本，已经发出的内容也无法撤回。健康状态下优先检查元数据，仍定期完整核验内容；没有“每次保存都立刻同步”的保证，网络退避、活动检查和资源限制会延后处理。

本机维护数据默认由**同一 profile 共享10GiB软预算**，不是每个配对各10GiB。高级存储设置可明确保存1–1024GiB整数上限，不改变项目选择，也不自动清理数据。统计范围与调度间隔见[运行参数](<docs/DEPLOYMENT.md#运行参数与本地预算>)。

### 中断与冲突处理

先看状态，不要用反复点击或删除日志来猜测上次是否成功。

- **冲突**：预览具体路径，默认保留双方；采用另一端内容也不能覆盖预览之后的新本机修改。
- **回收站**：恢复有校验的删除／替换副本；目标被占用时使用安全的新名称，不覆盖现有内容。
- **核对中断事务**：预览后再确认修复。仅在安全时补回缺失主文件，保留新的本机修改、旧备份和未确认的部分写入；修复后其他文件可以继续，歧义路径仍需显式解决冲突。
- **结果未确认**：先“核对状态”。同一请求有持久化结果；新的预览可显式替代受新策略阻止的旧修复，不会复活旧写入意图。

修复不是目录级事务或通用回滚。根目录、身份或备份损坏会停止操作。真正强杀进程留下的锁仍需管理员核对所有者，不能盲目删除；详见[安全边界](<docs/SECURITY.md>)。

## 会话归档不等于全部可续接

已配对项目可归档符合捕获条件的空闲会话日志、附件与相关产物快照。重复的同一档案按内容标识去重；已有档案不因本机当前未返回它而被删除。活动或暂不支持的会话会显示延后／不支持提示，不冒称已完成归档。

在“**会话**”中先预览，再明确确认“**导入新会话**”。导入只支持经过 native 格式与状态检查的较窄子集，使用新会话 ID；结果未知或部分成功时先核对已创建的 ID，不重复导入。日志中的 goal、schedule、权限、subagent/team/workflow、图像 offload 或未知插件领域，并不因为被保存就能恢复执行。

**同步、下载、归档和导入均不自动启动 agent，不恢复运行中的任务，也不复制其他 AI provider 凭据。**

## 登录、忽略与隐私

- 普通访问凭据默认24小时有效；“保持登录”使用设备绑定、轮换式续期，默认30天空闲期限、90天绝对期限，不是永久登录。
- 访问／续期秘密只保存在本插件的 profile-scoped 原生凭据记录。过期、撤销或续期结果未知时要求重新登录；重新登录后核对并明确恢复原配对，不静默沿用旧授权。
- 服务器地址、设备和真实目录绑定会被复核。不要在设备、账号或 profile 之间复制凭据及状态目录。
- 默认排除常见密钥／凭据文件、版本库数据库、依赖缓存、DSH/profile/同步状态及链接类文件。额外规则在项目根目录配置 `.dsh-syncignore`，每行一个相对 glob，不支持反向包含。

```text
logs/**
**/*.log
private-data/**
```

忽略文件是**该 Host 的本机上传／应用策略**，v2 不把它作为远端文件同步到其他设备。旧待处理内容也必须通过当前策略；不能靠重试绕过或偷偷删改旧清单。

**这不是秘密扫描器，也不是端到端加密。** 文件正文、会话、附件、路径、目录名称和头部元数据都可能含私人信息；服务器管理员能够读取存储内容。TLS 只保护传输，磁盘与备份应另行保护。

## 已有数据与换设备

已有云端项目统一出现在配对列表，不再按“旧版／双向项目”展示两套功能。每个项目独立成行；已知的来源目录、版本数量和时间用于区分，同名项目还可展开查看项目标识。来源目录只供辨识，不是本机写入目标。

- 旧自动上传设置与待处理队列保留，但新版不会自动发送或把它们转换为双向授权。
- 选择已有项目后，仍须预览并确认配对。历史项目有多个 head 时明确选择主版本，其余分支差异与原历史保留，缺失路径不被推断为删除。
- 接入双向同步后，服务器禁止该项目继续通过 v1 写入／旧 latest；确认页会说明这一影响。服务端保留的历史 ID 读取属于内部兼容能力，不是新版 GUI／CLI 恢复入口。
- 新设备先在 DSH 创建或添加目标工作区（可用空目录），登录后选择相同云端项目并完成配对。没有独立的旧备份下载、恢复、导入或“添加到DSH项目”流程。

本次不删除云端数据、不全局关闭旧客户端的服务端访问；未迁移项目仍保留服务端兼容协议。

## 安装与升级

原生 Plugins 的**插件地址输入框**可使用：

```text
https://github.com/HuYongJi/dsh_sync
```

它不是 npm registry。“安装源”保留正常 npm 源或组织认可的源；不能填写 GitHub 仓库网页。也可安装发布负责人提供的固定提交或已校验 tgz。安装到的版本取决于实际发布内容，不能由本地版本号或文档推断远端已经更新。

安装后按宿主提示重载／完整重启 DSH，再刷新原页面。客户端使用[预构建入口](<client/dist/client.js>)，复用宿主 React 和 SDK；不要关闭版本检查、脚本批准或另外启动一个 Web 服务来冒充原 GUI 更新。

“插件更新”通过原生插件管理器安装固定 Git 提交，只更新插件，不升级云服务器。**早于0.9.0的服务端应先升级**：可以保留原服务器与完整数据目录，但新版会使用版本2存储，旧二进制不能直接回退运行。管理员应先停止服务并做完整备份；步骤见[部署与升级](<docs/DEPLOYMENT.md>)。

## 开发与账号诊断

```sh
node scripts/build-client.mjs
node scripts/check-install.mjs
# 所有并行写入结束后再运行完整回归
node --test --test-isolation=none tests/*.test.mjs
node scripts/pack.mjs
```

[包定义](<package.json>)采用明确发布白名单。构建与本地打包不等于推送、安装或部署；真实配置、凭据、测试数据和研究副本不应进入发布包。

独立 [CLI](<src/cli.mjs>)仅保留自己的账号登录、状态、退出与帮助，不读取 GUI 原生凭据、不继承配对或续期权限。`preview/push/retry/list/restore` 在读取状态、凭据或发起网络请求之前即拒绝。原生命令仅保留 `/sync-status` 与 `/sync-logout`，项目操作统一使用双向同步面板。详见[版本记录](<docs/CHANGELOG.md>)。
